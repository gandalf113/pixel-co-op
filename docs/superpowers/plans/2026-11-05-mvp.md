# pixel-co-op MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Grywalne MVP pixel-co-op dla 1-4 graczy na LAN: lobby → przerwy/fale → budowa i power-upy → game over → wynik.

**Architecture:** Serwer Node (`ws`) jest autorytatywny: symulacja 30 Hz w czystych modułach `server/*` (bez I/O, z wstrzykiwanym RNG), sesja/lobby w `server/session.js` niezależnym od transportu, cienka warstwa HTTP+WS w `server/app.js`. Klient: vanilla JS (ES modules) + Canvas 2D, świat w 480x270 skalowany całkowicie, HUD na drugim canvasie w rozdzielczości okna, ekrany lobby/pauzy/wyniku w DOM. Kod ruchu i kolizji kafelkowej (`public/shared/*`) wspólny dla serwera i predykcji klienta.

**Tech Stack:** Node.js 24 (ESM, `node:test`), `ws` ^8, przeglądarka: Canvas 2D, ES modules. Zero innych zależności.

**Spec:** `docs/superpowers/specs/2026-11-05-mvp-implementation-design.md` (+ produktowe `docs/01-PRD.md` … `docs/05-TEST-PLAN.md`; ID wymagań typu `PRD-PLR-05`, `ITM-P-07`, `MOB-03` odnoszą się do nich). Wykonawca czyta spec i odpowiednie sekcje docs produktowych.

## Global Constraints

- Jedyna zależność runtime: `ws`. Żadnych devDependencies. Testy: `node --test` (`npm test`).
- `package.json`: `"type": "module"`; wszystko jako ES modules; start: `npm start` = `node server.js`.
- Klient nie ładuje niczego z sieci (CDN, fonty): tylko pliki z `public/`. Fonty systemowe (`monospace`).
- Żadnych PNG ani zewnętrznych grafik: sprite'y jako tablice stringów + paleta w `public/client/sprites.js`.
- Każda liczba balansu pochodzi z `public/balance.json` (dostęp przez `makeRules`/obiekt balance). W kodzie wolno mieć tylko stałe niebalansowe (np. 480x270, kody klawiszy).
- Moduły `server/*` poza `server/app.js` nie robią I/O ani nie czytają zegara/`Math.random`; czas przez `dt`, losowość przez `rng()`.
- Komentarze: domyślnie brak; najwyżej jedna krótka linia „dlaczego”. Bez historii, ticketów, „jak wcześniej”.
- Teksty UI po polsku, dokładnie: `FALA {n}`, `PRZERWA {m}:{ss}`, `BROŃ LV {n}`, `[E] podnieś: {nazwa}`, `nic`, `Czekam na hosta…`, `Gra w toku`, `Serwer pełny`, `[G] Gotowy`. Nazwy przedmiotów: `Kawałek ściany`, `Działko 30 s`, `Mina`. Trudności: `Łatwy`, `Normalny`, `Trudny`, `Koszmar`.
- Typy przedmiotów (klucze): `wall`, `turret30`, `mine`. Typy potworów: `slime`, `runner`, `brute`.

## Review Focus

1. **Karta w tle / brak inputu przez długi czas** (przeglądarka dławi `setInterval`) → gracz stoi, NIE jest zawieszany ani rozłączany; zawieszenie tylko po zamknięciu WS. Test: Task 9 `no input for 10 s does not suspend`.
2. **Wrogie / zepsute wiadomości** (nie-JSON, `NaN`, `1e308`, nieznany typ, `seq` wstecz, `level: 7`, nick 500 znaków ze znakami sterującymi) → ignorowane lub przycięte, serwer działa dalej. Test: Task 9 `malformed messages are ignored`.
3. **Dwie karty na jednym komputerze** (obie loopback) → dokładnie jeden host (najwcześniej dołączony lokalny). Test: Task 9 `only first local player is host`.
4. **Okno mniejsze niż 480x270** → skala ≥ 1, brak zerowych/ujemnych wymiarów. Test: Task 11 `computeScale never below 1`.
5. **Akcja w trakcie animacji podnoszenia / powalenie z przedmiotem** → `E`/`R`/`Spacja` w trakcie `busy` ignorowane; powalony upuszcza przedmiot pod nogi. Test: Task 8 `actions ignored while busy`, `downed drops held item`.

**Interfaces:**

- Produces:
